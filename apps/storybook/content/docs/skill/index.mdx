Kit 的中文 Skill 指导 coding agent 选择组件、管理聊天状态、接入对话后端、配置数据库和企业登录。
每个 Skill 都可以独立复制使用，涉及公开 API 的 Skill 附有接口参考和可编译示例。
三个对话 Skill 的完整离线包还包含将组件、示例和 Kit SDK 源码复制到业务项目的脚本与资产。

Skill 是写代码时读取的指南，不是运行时插件，也不会替应用创建会话或调用百炼。
React 页面使用 `kit-chat-ui` 和 SDK 的 `/hooks`，Vue 3 页面使用 `kit-chat-ui-vue` 和 `/hooks-vue`。
`kit-components` 和 `use-kit-chat` 优先使用用户指定的框架，再根据已有目标项目判断。
仍无法确定时进入 Question 阶段询问用户。

| 想完成的工作 | 从哪个 Skill 开始 |
| --- | --- |
| 选择消息、输入、附件、反馈和页面辅助组件 | `kit-components` |
| 把已有后端连接到页面，管理发送与会话状态 | `use-kit-chat` |
| 自己有百炼后端，需要适配请求和流数据合同 | `kit-chat-provider` |
| 为 Kit Server 选择数据库并验证启动 | `kit-database` |
| 接入 Keycloak 员工登录并验证成员绑定 | `kit-keycloak` |

完整对话页面通常会同时使用对话相关的三个 Skill。只有 UI 组合需求时，可以单独使用
`kit-components`；已有稳定 Provider 时，不需要重复实现后端适配。

## 获取与阅读

先阅读[安装与更新](/docs/skill/install)，再将 Skill 目录复制到 coding agent 支持的目录。
也可以直接下载[全部 Skill 的离线包](/skills/kit-skills.tgz)并阅读其中的 `SKILL.md`。
复制完整目录即可保留每个 Skill 的元数据和随附资源。

Skill 源文件位于 `scripts/skills/src/`，最终目录生成到 `assets/skills/<name>/`，离线压缩包
由 `pnpm pack:skills` 生成到 `assets/skills/dist/`。三个对话 Skill 离线包内的 `scripts/install.mjs`
可将所需组件、示例和 SDK 源码复制到应用，组件和示例通过相对路径导入 `src/sdk/` 的公开入口。

## API 与示例如何保持一致

公开 TypeScript 导出是 API 结构的事实来源。`pnpm gen:skills` 更新中文 API 参考与本站
示例；`pnpm check:skills` 只检查，不修改文件，发现公开接口、组件覆盖或示例内容漂移时失败。
`pnpm pack:skills` 生成离线包。

API 签名、Props 和类型由源码同步。用途、默认行为和接入约束由中文参考资料说明，并与
组件和 SDK 文档核对。本站嵌入的代码来自 Skill 的同一份 TS/TSX 示例，不维护另一套代码。
新增公开组件、子组件或兼容别名时，必须一起补齐 Skill 索引与 API 参考。

运行时 API 的详细用法见[组件总览](/docs/components)与 [SDK 与 Kit 数据接入](/docs/sdk)。
