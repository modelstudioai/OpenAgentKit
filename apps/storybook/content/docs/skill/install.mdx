---
title: 安装与更新
description: 从仓库或离线包获取中文 Skill，并在更新时保留本地修改
---

Skill 通过完整目录交付。每个目录中的 `SKILL.md` 是入口。按需随附 `references/` 中的
API 和行为说明，以及 `examples/` 中的 TypeScript 示例。
三个对话 Skill 的离线包在 `scripts/` 和 `assets/kit/` 中提供源码复制脚本与资产。

## 获取离线包

| 内容 | 下载 |
| --- | --- |
| 全部 Skill | [kit-skills.tgz](/skills/kit-skills.tgz) |
| 组件组合 | [kit-components.tgz](/skills/kit-components.tgz) |
| 会话状态与交互 | [use-kit-chat.tgz](/skills/use-kit-chat.tgz) |
| 默认与自建后端接入 | [kit-chat-provider.tgz](/skills/kit-chat-provider.tgz) |
| SQLite、MySQL 和 PostgreSQL 接入 | [kit-database.tgz](/skills/kit-database.tgz) |

将压缩包解压到临时目录，确认顶层 Skill 目录及其内容，再复制到当前 coding agent 支持的
Skill 目录。单个压缩包的顶层目录就是 Skill 名称；合并包包含所有 Skill 的同级目录。
支持项目级 Skill 的工具应优先按项目安装，具体发现路径以所用工具的文档为准。

例如，工具使用项目级 `.agents/skills/` 时，安装后的结构为：

```text
.agents/skills/
  kit-components/
    SKILL.md
    references/
    examples/
    scripts/
    assets/
  use-kit-chat/
    SKILL.md
    references/
    examples/
    scripts/
    assets/
  kit-chat-provider/
    SKILL.md
    references/
    examples/
    scripts/
    assets/
  kit-database/
    SKILL.md
```

每个 Skill 都可独立安装。复制完整目录可保留元数据和入口引用的全部资源。

## 接入业务项目

在目标应用使用三个对话 Skill 时，让 coding agent 阅读其中的 `references/copy-in.md`。
从解压的 Skill 目录运行脚本，传入应用目录和所需组件：

```bash
node "<Skill 目录>/scripts/install.mjs" --dir "<应用目录>" chat
```

所选组件、传递依赖和主题会放入应用的 `src/components/kit/`。省略组件名和示例时只复制 Kit SDK。
SDK 源码会放入 `src/sdk/`，复制后的组件通过相对路径导入它的公开入口。
复制示例时，使用 `--example <文件名>`，例如在 `use-kit-chat` 的脚本中传入
`--example experience.tsx`。脚本会带上所需组件和随附文件，示例落在
`src/kit-examples/use-kit-chat/`。应用统一构建这些源码，并用自己的包管理器安装第三方依赖。

## 从仓库生成

在仓库根目录安装依赖后执行：

```bash
pnpm gen:skills
pnpm check:skills
pnpm pack:skills
```

源文件位于 `scripts/skills/src/<skill-name>/`；最终目录生成到 `assets/skills/<skill-name>/`，
完整离线包写入 `assets/skills/dist/`。生成物由上述命令维护。
文档站构建会校验同步结果并准备下载文件，不会替开发者自动改写已跟踪的源或示例。

压缩包保留打包时源文件的实际修改时间（精确到秒），解压后可直接查看。该时间来自当前
工作目录的文件，不代表 Git 最后提交时间；内容或修改时间变化都会改变压缩包。

Skill 安装在 coding agent 的工具目录。应用运行时使用复制后的组件源码和本地 SDK。

## 更新已有 Skill

1. 将新离线包解压到临时目录，保留当前目录的备份。
2. 对比 `SKILL.md`、`references/` 和 `examples/`；确认新增接口、行为变化与本地定制。
3. 合并需要保留的定制，再替换整个 Skill 目录。不要直接覆盖仍有修改的文件。
4. 让 coding agent 重新读取入口，确认相对链接可打开，并在目标项目运行类型检查。

Skill 随当前仓库 API 更新。旧版本 Kit 或已修改的 copy-in 组件可能与新参考不同，应以
目标项目实际安装的类型和组件源码为准，不要直接套用新版本字段。

## 试用提示词

工具识别到 Skill 后，可以用中文描述任务。

```text
用 $kit-components 搭建带 Sender 和 Attachments 的对话面板。
上传请求通过调用方提供的回调执行，草稿保持可编辑。
```

```text
用 $use-kit-chat 把这个页面接入已有 ChatProvider。
实现发送、停止、切换会话，以及允许和拒绝工具调用。
```

```text
用 $kit-chat-provider 接入返回原始 SSE 的百炼业务后端。
编写适配器前先核对上游就绪和完整历史回放的接口合同。
```

```text
用 $kit-database 把这个项目接到我已有的 PostgreSQL，验证启动和迁移记录。
```

浏览器中的应用登录令牌与百炼 Provider 凭据不同。自建后端接入始终把百炼 API Key 留在
服务端；下载 Skill 不需要提供凭据。
