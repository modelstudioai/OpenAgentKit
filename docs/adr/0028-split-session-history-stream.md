# ADR-0028：会话历史分页和纯实时 SSE

## 背景

协议 v2 在服务端打开 SSE 时读完全部历史，再将历史和实时事件从同一连接交付。
员工端和管理员调试均已有独立的历史分页接口，需要用各自的历史接口恢复消息，
同时保留同一会话的实时快照、续传和业务状态保护。

## 决策

- 两端沿用各自的 `/events` 和 `/stream` 路径。历史使用升序分页，SSE 只发送实时变更。
  `ready` 表示可接收实时更新，过期游标收到 `reset → ready` 后通过历史分页重建。
- 标准事件适配器必填 `listEvents`。Chat Controller 先建立订阅，再读取历史并缓冲实时更新，
  以 `event_id` 对账并原子发布。发送与审批等待这一步完成。
- 会话继续共享上游连接。服务端按需完成发送和审批的运行状态校验，独立记录实时传输游标。
  上游断流关闭本代 SSE，浏览器重连并按新游标恢复观察。
- 协议主版本更新至 3，统一校验员工和调试会话的协议版本。分帧和事件语义沿用 SDK
  `SessionEvent`。

## 理由与后果

实时订阅可在历史分页前就绪，客户端用同一列表接住历史读取期间到达的事件。
现有历史分页、会话归属及审批端点继续承担各自职责。Kit Server、SDK、Web/H5 和 Console
需要同步升级。自建原始百炼适配器保留由其归一器合并历史与增量的接入方式。

## 备选方案

保留 v2 组合流需要长期维护两种就绪及复位语义，因此统一采用 v3。
